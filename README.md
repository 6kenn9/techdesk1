# TechDesk

Вебзастосунок для автоматизації роботи комп’ютерного сервісного центру з підсистемами паспортизації пристроїв та обліку робіт.

Клієнт реєструє звернення, відстежує ремонт, погоджує кошторис і завантажує документи. Майстер проводить діагностику, веде паспорт пристрою та резервує запчастини. Адміністратор керує складом, прейскурантом, довідником моделей, користувачами та аналітикою.

## Запуск через Docker Compose

Потрібні Docker і Docker Compose v2. Скопіюйте `.env.example` у `.env` і впишіть у `JWT_SECRET` випадковий ключ (команда для генерації — у коментарі в `.env.example`). Демодані з'являються лише за `DEMO_MODE=true`; за замовчуванням демо-режим вимкнено, а без `JWT_SECRET` сервер поза демо-режимом не запуститься. Із кореня проєкту виконайте:

```sh
docker compose up --build
```

Відкрийте [TechDesk](http://localhost:5173) або [документацію API](http://localhost:8000/docs). Перший запуск створює таблиці через Alembic і за `DEMO_MODE=true` заповнює порожню базу демоданими. Compose зберігає дані PostgreSQL в іменованому томі.

## Запуск без Docker

Потрібні Python 3.11+, Node.js 22+ і PostgreSQL 15+. Створіть окрему базу та користувача з правами власника. Скопіюйте `.env.example` у `.env` і встановіть `DATABASE_URL` у форматі `postgresql+psycopg://користувач:пароль@localhost:5432/techdesk`. Символи пароля, що мають значення в URL, потрібно закодувати.

У першому терміналі:

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

У другому терміналі:

```sh
cd frontend
npm ci
npm run dev
```

На Linux і macOS замість `.\.venv\Scripts\python.exe` використовуйте `.venv/bin/python`. Vite передає запити `/api` серверу FastAPI, тому окрема конфігурація CORS для локального запуску не потрібна. `PUBLIC_URL` задає адресу, яку містять коди у PDF. Щоб відкривати коди з телефона, ця адреса має бути доступною з телефона.

## Демонстрація на захисті

| Роль | Електронна пошта | Пароль |
| --- | --- | --- |
| Адміністратор | admin@techdesk.ua | admin123 |
| Майстер ноутбуків і ПК | master1@techdesk.ua | master123 |
| Майстер мобільної техніки | master2@techdesk.ua | master123 |
| Майстер плат і консолей | master3@techdesk.ua | master123 |
| Клієнти | client1@techdesk.ua … client4@techdesk.ua | client123 |

- На сторінці входу введіть пошту й пароль потрібної ролі з таблиці вище.
- У журналі знайдіть заявку `TD-<рік>-0004` зі статусом «Очікує погодження вартості». Відкрийте її в кабінеті клієнта та погодьте кошторис.
- Як майстер ноутбуків відкрийте цю заявку, позначте її готовою до видачі й перегляньте в паспорті зміну накопичувача. Завершіть заявку та завантажте гарантійний талон.
- У майстрі приймання введіть `TD-ASU-10482`, щоб переглянути паспорт і чинну гарантію. На публічній сторінці етап ремонту шукають лише за номером заявки (`TD-<рік>-…`): серійний номер надруковано на корпусі, тож за ним сторонній міг би дізнатися, що пристрій у сервісі.
- Заявка зі статусом «Готова до видачі» і доставкою Новою Поштою: як адміністратор прийміть оплату, внесіть номер накладної (14 цифр) і завершіть заявку. Клієнт отримає ТТН у Telegram.
- У кабінеті клієнта відкрийте завершену заявку й поставте оцінку від 1 до 5 зірок. Середня оцінка центру й кожного майстра з'явиться в аналітиці.
- Як адміністратор перевірте складські рухи, залишки й аналітику. Дата в номері заявки залежить від дати першого заповнення бази.

Дані завантажуються один раз за умови, що таблиця користувачів порожня. Команду `python seed.py` можна запустити вручну після міграції в окремій демонстраційній базі.

## Відновлення пароля листом

На сторінці входу є посилання «Забули пароль?». Користувач вводить пошту й отримує лист з одноразовим посиланням, яке діє 30 хвилин. Так само пароль може задати той, хто реєструвався через Google.

Щоб листи надсилалися, додайте в `.env` дані поштової скриньки. Для Gmail увімкніть двоетапну перевірку й створіть «пароль застосунку» в налаштуваннях облікового запису Google (звичайний пароль від пошти не підійде):

```
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=ваша.скринька@gmail.com
SMTP_PASSWORD=пароль застосунку з 16 літер
MAIL_FROM=ваша.скринька@gmail.com
```

Без цих налаштувань лист не надсилається, а його текст із посиланням з'являється в журналі сервера (`docker compose logs backend`).

## Telegram-бот

Бот запускається, якщо в `.env` задано `TELEGRAM_BOT_TOKEN` і `TELEGRAM_BOT_USERNAME`. Користувач підключає його в кабінеті кнопкою «Підключити Telegram».

Що надсилає бот:

- клієнту — зміну кожного етапу ремонту; кошторис із підсумком, орієнтовним строком і кнопками «Погодити» / «Відхилити»; повідомлення про готовність або номер накладної Нової Пошти;
- клієнту — нагадування за 7 днів до кінця гарантії на ремонт;
- клієнту — пораду на профілактику через пів року після ремонту ноутбука, ПК, моноблока, міні-ПК чи консолі, якщо пристрій відтоді не повертався в сервіс;
- майстру — призначену заявку й рішення клієнта щодо кошторису.

Внизу чату є меню: клієнт бачить «Мої заявки», «Гарантія», «Нова заявка», «Допомога», працівник — «Мої заявки» і «Допомога». Остання кнопка меню призупиняє сповіщення або вмикає їх знову; на паузі чат лишається прив'язаним і команди працюють. Те саме можна зробити в кабінеті на сайті. Ті самі команди є в кнопці «Меню» поруч із полем введення. Нагадування бот перевіряє щогодини і кожне надсилає один раз.

## Резервні копії бази

Docker має бути запущено. У Windows виконайте з кореня проєкту:

```
scripts\backup.bat
```

Копія збережеться в `backups\techdesk_<дата_час>.sql`. Щоб повернути базу до стану копії, виконайте:

```
scripts\restore.bat backups\techdesk_2026-11-10_18-40.sql
```

У Linux і macOS ці самі дії роблять `./scripts/backup.sh` і `./scripts/restore.sh <файл>`. Папку `backups` додано в `.gitignore`: копії містять персональні дані клієнтів, тому їх не публікують.

## Структура і бізнес-правила

- `frontend/src/views` — екрани Vue. Vue Router обмежує доступ до маршрутів за роллю, Pinia керує сеансом і фільтрами, Chart.js відображає аналітику.
- `backend/app/api` — маршрути FastAPI, JWT і перевірка дозволів на сервері. Клієнту доступні лише власні паспорти й заявки.
- `backend/app/services/domain.py` — переходи станів, версія кошторису, складські операції, гарантії та журнал змін характеристик.
- `backend/app/models` і `backend/migrations` — моделі SQLAlchemy та схеми PostgreSQL. Характеристики зберігаються в JSONB.
- `backend/app/api/pdf_generator.py` — квитанції й талони з кириличним шрифтом DejaVu Sans та QR-кодами.

Додавання деталі блокує її рядок у PostgreSQL, перевіряє залишок і в одній транзакції зберігає списання, рядок кошторису й підсумок заявки. Закупівельна та продажна ціни фіксуються на момент додавання. Видалення позиції або скасування до початку ремонту повертає резерв. Кошторис можна редагувати до надсилання клієнту, після повернення непогодженого кошторису на діагностику та під час ремонту. Сервер запам'ятовує склад кошторису, який погодив клієнт: будь-яка зміна під час ремонту (додати, прибрати, замінити позицію чи змінити ціну) знову вимагає згоди клієнта, а повернення до погодженого складу відновлює попередню згоду. При погодженні сервер перевіряє суму й версію позицій.

Діагностику можна почати лише після призначення відповідального майстра. Змінювати заявку може лише її відповідальний майстер або адміністратор; вільну заявку майстер спершу бере собі. Заявку можна скасувати на будь-якому етапі до готовності до видачі. Скасування до початку ремонту повертає зарезервовані запчастини на склад; скасування під час ремонту вимагає причини, а вже встановлені деталі не повертаються (невикористані майстер прибирає з кошторису до скасування). Скасований пристрій лишається в сервісі, доки його не позначать повернутим клієнту: до того на нього не можна відкрити нову заявку чи передати іншому власнику. Завершити заявку можна тільки після обліку повної оплати. Гарантійний випадок дозволено лише для пристрою з чинною гарантією: роботи й деталі фіксуються в кошторисі, але сума до сплати клієнтом дорівнює нулю, а витрати на деталі враховуються в аналітиці.

Вхід блокується на 5 хвилин після 5 невдалих спроб для пари «IP + e-mail». Тимчасовий пароль, виданий адміністратором, дає доступ лише до зміни пароля (це перевіряє сервер), а вимкнення облікового запису завершує всі його сеанси. Реєстрація обмежена 10 запитами на годину, а публічне відстеження — 30 запитами на хвилину з однієї адреси.

Швидке оформлення. Клієнт може залишити заявку без реєстрації на `/quick`: достатньо імені, телефону, типу пристрою, моделі (є підказки з довідника) та опису несправності. Система створює гостьовий кабінет без пошти й пароля та видає особисте посилання `/claim/<токен>` (діє 30 днів, у базі зберігається лише хеш); пізніше клієнт може додати пошту й пароль. Для телефону, який уже має кабінет, нове посилання не видається, щоб чужою заявкою не можна було перехопити доступ. Форма захищена обмеженням 5 заявок на годину та полем-приманкою для ботів. Зареєстрований клієнт обирає один зі своїх пристроїв і описує проблему. Працівник на `/orders/intake` знаходить клієнта за телефоном, обирає його пристрій або вносить новий і створює заявку одним кроком; після цього доступні квитанція й наліпка. Серійний номер необов’язковий, але діагностику не можна почати, поки його не внесено в паспорт.

Показник виручки підсумовує вартість завершених замовлень за датою завершення. Облік отриманої оплати ведеться окремо. Розрахунковий прибуток віднімає закупівельну вартість списаних деталей. Поточна завантаженість майстра визначається кількістю активних заявок.

## Перевірка

Створіть **порожню** тестову базу PostgreSQL із назвою, яка закінчується на `_test`. Тести самі застосують і відкочують міграцію в цій базі. Модульні тести правил (`tests/test_rules.py`) працюють і без бази.

```powershell
cd backend
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
$env:TEST_DATABASE_URL = 'postgresql+psycopg://techdesk:techdesk@localhost:5432/techdesk_test'
.\.venv\Scripts\python.exe -m pytest -q
```

Збірка інтерфейсу:

```sh
cd frontend
npm ci
npm run build
```

## Налаштування окремого робочого середовища

Для робочої бази встановіть `DEMO_MODE=false`, окремі облікові дані PostgreSQL, `JWT_SECRET` із щонайменше 32 випадкових символів і адресу `PUBLIC_URL` з HTTPS. Після міграції створіть першого адміністратора командою `python create_admin.py`. Демооблікові записи призначені для окремої демонстраційної бази.
