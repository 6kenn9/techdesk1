# TechDesk

Вебзастосунок для автоматизації роботи комп’ютерного сервісного центру з підсистемами паспортизації пристроїв та обліку робіт.

Клієнт реєструє звернення, відстежує ремонт, погоджує кошторис і завантажує документи. Майстер проводить діагностику, веде паспорт пристрою та резервує запчастини. Адміністратор керує складом, прейскурантом, довідником моделей, користувачами та аналітикою.

## Запуск через Docker Compose

Потрібні Docker і Docker Compose v2. Із кореня проєкту виконайте:

```sh
docker compose up --build
```

Відкрийте [TechDesk](http://localhost:5173) або [документацію API](http://localhost:8000/docs). Перший запуск створює таблиці через Alembic і заповнює порожню базу демоданими. Compose зберігає дані PostgreSQL в іменованому томі.

## Запуск без Docker

Потрібні Python 3.11+, Node.js 22+ і PostgreSQL 15+. Створіть окрему базу та користувача з правами власника. Скопіюйте `.env.example` у `.env` і встановіть `DATABASE_URL` у форматі `postgresql+psycopg://користувач:пароль@localhost:5432/techdesk`. Символи пароля, що мають значення в URL, потрібно закодувати.

У першому терміналі:

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

У другому терміналі:

```sh
cd frontend
npm ci
npm run dev
```

На Linux і macOS замість `.\.venv\Scripts\python.exe` використовуйте `.venv/bin/python`. Vite передає запити `/api` серверу FastAPI, тому окрема конфігурація CORS для локального запуску не потрібна. `PUBLIC_URL` задає адресу, яку містять коди у PDF. Щоб відкривати коди з телефона, ця адреса має бути доступною з телефона.

## Демонстрація на захисті

| Роль | Електронна пошта | Пароль |
| --- | --- | --- |
| Адміністратор | admin@techdesk.ua | admin123 |
| Майстер ноутбуків і ПК | master1@techdesk.ua | master123 |
| Майстер мобільної техніки | master2@techdesk.ua | master123 |
| Майстер плат і консолей | master3@techdesk.ua | master123 |
| Клієнт | client1@techdesk.ua | client123 |

- На сторінці входу натисніть картку потрібної ролі.
- У журналі знайдіть заявку `TD-<рік>-0004` зі статусом «Очікує погодження вартості». Відкрийте її в кабінеті клієнта та погодьте кошторис.
- Як майстер ноутбуків відкрийте цю заявку, позначте її готовою до видачі й перегляньте в паспорті зміну накопичувача. Завершіть заявку та завантажте гарантійний талон.
- У майстрі приймання введіть `TD-ASU-10482`, щоб переглянути паспорт і чинну гарантію. Пошук за цим номером доступний і на публічній сторінці, де показується лише етап останньої заявки.
- Як адміністратор перевірте складські рухи, залишки й аналітику. Дата в номері заявки залежить від дати першого заповнення бази.

Дані завантажуються один раз за умови, що таблиця користувачів порожня. Команду `python seed.py` можна запустити вручну після міграції в окремій демонстраційній базі.

## Структура і бізнес-правила

- `frontend/src/views` — екрани Vue. Vue Router обмежує доступ до маршрутів за роллю, Pinia керує сеансом і фільтрами, Chart.js відображає аналітику.
- `backend/app/api` — маршрути FastAPI, JWT і перевірка дозволів на сервері. Клієнту доступні лише власні паспорти й заявки.
- `backend/app/services/domain.py` — переходи станів, версія кошторису, складські операції, гарантії та журнал змін характеристик.
- `backend/app/models` і `backend/migrations` — моделі SQLAlchemy та схеми PostgreSQL. Характеристики зберігаються в JSONB.
- `backend/app/api/pdf_generator.py` — квитанції й талони з кириличним шрифтом DejaVu Sans та QR-кодами.

Додавання деталі блокує її рядок у PostgreSQL, перевіряє залишок і в одній транзакції зберігає списання, рядок кошторису й підсумок заявки. Закупівельна та продажна ціни фіксуються на момент додавання. Видалення позиції або скасування до початку ремонту повертає резерв. Кошторис можна редагувати до надсилання клієнту або після повернення непогодженого кошторису на діагностику. При погодженні сервер перевіряє суму й версію позицій.

Показник виручки підсумовує вартість завершених замовлень за датою завершення. Облік отриманої оплати ведеться окремо. Розрахунковий прибуток віднімає закупівельну вартість списаних деталей. Поточна завантаженість майстра визначається кількістю активних заявок.

## Перевірка

Створіть **порожню** тестову базу PostgreSQL із назвою, яка закінчується на `_test`. Тести самі застосують і відкочують міграцію в цій базі.

```powershell
cd backend
$env:TEST_DATABASE_URL = 'postgresql+psycopg://techdesk:techdesk@localhost:5432/techdesk_test'
.\.venv\Scripts\python.exe -m pytest -q
```

Збірка інтерфейсу:

```sh
cd frontend
npm ci
npm run build
```

## Налаштування окремого робочого середовища

Для робочої бази встановіть `DEMO_MODE=false`, окремі облікові дані PostgreSQL, `JWT_SECRET` із щонайменше 32 випадкових символів і адресу `PUBLIC_URL` з HTTPS. Після міграції створіть першого адміністратора командою `python create_admin.py`. Демооблікові записи призначені для окремої демонстраційної бази.
